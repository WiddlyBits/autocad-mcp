# Troubleshooting

Read this when something is actually wrong. It lives here rather than in `SKILL.md`
because at most two or three of these fire in a session, and `SKILL.md` is re-read by
every request in it.

| Symptom | Likely cause | Fix |
|---|---|---|
| `preflight` says `select: false` or `probes: false` | libraries not loaded — normal state at the start of every session before `init` runs, or after an AutoCAD restart | `system(operation="init")` |
| `system(status)` says dispatch not loaded | `mcp_dispatch.lsp` isn't in the *current* document | `setup-and-autoload.md` — APPLOAD Startup Suite, not `acaddoc.lsp` |
| `(mcp:sel)` returns nothing | nothing was handed over | ask for `HS` + Enter (Rule 1). Don't guess, and don't ask him to re-select in the hope the grip selection survives this time — it never does |
| A verb returns `WRONG-DOC` | focus is on another document or tab | the payload names the actual `dwg`/`ctab` — use those, don't spend a round trip re-probing |
| A verb reports a high `skipped` count | the set isn't what you assumed — non-LINE entities in a line operation, chunked MTEXT, text that didn't contain the substring | `(mcp:sel-dump)` and read the types before re-running |
| Dispatch timeout / "Screenshot capture failed" right after an AutoCAD restart | cached window handle went stale — but note: since A-4, `_dispatch_unlocked` checks `IsWindow()` before each dispatch and re-acquires transparently; you should only see a timeout here if the re-acquisition also fails (AutoCAD isn't running at all) | `system(operation="init")` re-acquires it; if every dispatch returns `autocad_not_found` immediately, AutoCAD itself is not running |
| `execute_lisp` times out but screenshots still work | an ActiveX object-*creation* call hung the dispatcher | `activex-and-lisp-limits.md` for the recovery steps — don't just retry, a blind retry can double-apply |
| First `execute_lisp` right after the user clicks another tab returns `error: "timeout_mutating"`, `may_have_applied: true` | intermittent after a focus change (2026-10-08: 2 of the 3 Draft 1 tab switches; the 3 switches back to a `.dwt` did not time out) | With dispatcher v2 loaded (needs APPLOAD of `mcp_dispatch.lsp` or a restart), a trigger that never reached the prompt comes back as `timeout_not_dispatched` (`may_have_applied: false`) after one automatic retry. That result is safe to re-send. On v1, or when the result is `timeout_mutating`: `system(status)` — `idle` plus the expected `preflight.dwg` means the dispatcher is fine. **Read-only call** (e.g. `(mcp:whoami)`): just retry, it worked every time. **Mutating call**: check state first (entity count or the entity itself) before re-sending, since `may_have_applied` is real. **Check the version with `execute_lisp (list *mcp-dispatcher-version* (mcp:whoami))`** — first element 2. The ping reply is read inside `initialize()` and never surfaced, so the `init` payload shows no `"dispatcher":2`. Live check 2026-10-08 with v2: 3 of 3 tab switches dispatched cleanly (no timeout to classify); with the OPTIONS dialog held open, the call returned `timeout_not_dispatched`, left 0 `cmd_`/`run_` files in `C:\temp`, and the next call after closing the dialog succeeded |
| First call on a document just opened or switched to fails `no function definition: MCP:WHOAMI` (or any `mcp:` verb) | the dispatcher autoloads per document, but `mcp_probes.lsp`/`mcp_select.lsp` were loaded by `init` into the *previous* document only (2026-10-08: Drawing2 and the `.dwt`, each first visit) | `system(operation="init")` once on that document. The failed call did dispatch, so nothing ran — safe to re-send |
| `execute_lisp` payload is an opaque `<<ccr:…,262B>>` instead of the result | the result was replaced by a reference in transit; no tool here resolves it (seen once, `(list *mcp-dispatcher-version* (mcp:whoami))` on a `.dwt`, 2026-10-08) | Re-ask for less: `(list (getvar "DWGNAME") (getvar "DWGPREFIX") (getvar "DBMOD"))` |
| `drawing(operation="save_as")` errors "Unknown drawing operation" | that operation name doesn't exist | use `drawing(operation="save", data={"path": ...})` |
| `entity(count)` on a layer you just "deleted" isn't zero, or a purge removes more/less than expected | likely a `CLAYER` or nested-block-definition issue, not a real problem | `activex-and-lisp-limits.md` |
| A probe answers plausibly but with the behaviour you just fixed | old definitions still resident | `system(operation="init")` re-loads probes and select; `mcp_dispatch.lsp` needs APPLOAD or a restart |
| `claude mcp add ...` fails with "unknown option '-m'" or "'--%'" in PowerShell | bare `claude` mis-parses args after `--` | `setup-and-autoload.md` for the `claude.exe`-direct invocation |
